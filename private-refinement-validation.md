## Mobile loading-performance audit

- **Production bundle baseline:** The current build succeeds but emits one 1,327,340-byte JavaScript file (312.93 kB gzip), 162,373 bytes of CSS (26.46 kB gzip), and a 369.56 kB generated HTML entry (106.04 kB gzip). Vite reports the JavaScript chunk above its 500 kB advisory threshold.
- **Route-loading cause:** `App.tsx` eagerly imports Home plus Product Detail, Shop, COA, checkout, account, admin, authentication, legal, and utility pages. Route-level lazy imports can keep non-home code out of the initial mobile path without changing route behavior.
- **Real image payload:** Following storage redirects showed 22 referenced images totaling 30,652,518 bytes. The clinic hero is 2.30 MB, the Who We Are photo is 2.34 MB, the desktop-only gym intro is 2.41 MB, the shared logo is 0.83 MB, and most vial images are 1.29–1.54 MB each.
- **Eager image cause:** Shared ProductCard, AboutSection, related-product, and several detail/COA images currently omit `loading`, `decoding`, and priority hints. Because all 16 cards are rendered, the catalog can schedule a large below-the-fold image payload even before a mobile visitor reaches it.
- **Mobile intro protection:** Home does not mount the gym intro below 768 px, so the 2.41 MB desktop intro image is intentionally excluded from the mobile path and that behavior must remain.
- **Fonts:** The document preconnects to Google Fonts and requests only the three established families and their used weights. No additional font family is needed for the redesign.
- **Runtime behavior:** Current-session browser and network logs showed no HTTP error or browser exception. Development-only customer/auth status queries ranged from roughly 0.9 to 1.8 seconds; no provider call was made. The actionable loading bottlenecks are static bundle/image scheduling rather than a new runtime failure.
- **Safe optimization path:** Preserve the visible hero and logo, lazy-load below-the-fold catalog/About/related images, decode large images asynchronously, split non-home route modules, and create content-preserving responsive WebP derivatives for multi-megabyte photographs and vial images. Re-measure after implementation.
- **Derivative result:** Deterministic, crop-free WebP conversion reduced 21 PNG assets from 30,559,202 bytes to 3,632,588 bytes, an 88.1% reduction, while preserving their original aspect ratios.
- **Visual derivative check:** The 1536×1024 clinic hero derivative retained the full room composition, photographed signage, lighting, color balance, and Retatrutide vial at 216,400 bytes. A representative 1000×1499 Retatrutide 30 mg derivative retained the blue cap, product logo, strength, label lettering, and research-only footer at 170,408 bytes. No semantic image edit or crop was applied.
